# Deploy runbook (v0.2 learner test)

PatternPilot runs on **Render**, region **Singapore** (the closest Render region to Seoul and Tokyo):

- **Web service `patternpilot`** (Starter, about US$7/month): one always-on instance, built from the [`Dockerfile`](../Dockerfile). One Node process serves the website and `/api` from the same domain. HTTPS certificates are automatic.
- **Postgres `patternpilot-db`** (Basic-256mb, about US$6/month, PostgreSQL 17): question bank and waitlist. It has no public access; only the web service can reach it.
- Everything is described in [`render.yaml`](../render.yaml). `DATABASE_URL` is wired automatically. `ADMIN_SECRET` is generated by Render and never stored in the repo.

**Total: about US$13/month, plus the domain (about US$10–15/year).**

On every deploy, Render builds the image and then runs the **pre-deploy step** (migrate the database, then seed the 3 passages). Both are safe to repeat. Only after they succeed does Render switch traffic to the new version, after `/api/healthz` responds. If the pre-deploy step fails, the old version keeps running.

> Restarting or redeploying ends any practice session that is in progress, because sessions live in server memory. Learners' history is safe (it is stored in their browser). Avoid deploying while a learner test is in progress.

## Redeploy

Auto-deploy is **off**, so pushing code doesn't change the live site by itself.

1. Make sure the change is merged into `main` on GitHub.
2. Render dashboard → `patternpilot` → **Manual Deploy** → **Deploy latest commit**.
3. Watch **Events**. The deploy is done when it says *Deploy live*. Then open the site and run one passage.

## Roll back

Render dashboard → `patternpilot` → **Events** → find the last good deploy → **Rollback**.

Rollback changes the code, not the database. If the bad deploy included a database migration, don't roll back; ask a developer for a forward fix ([step-3-postgres.md](step-3-postgres.md) explains why).

## Read logs

Render dashboard → `patternpilot` → **Logs**. You can search and filter by time. Pre-deploy (migration and seed) output is in **Events** → the deploy → its log. A healthy start logs `Server listening`; a seed line looks like `{ inserted: 0, existing: 3 }`.

## Back up the database

- **Automatic:** Render keeps backups of paid databases. Dashboard → `patternpilot-db` → **Recovery**. You can restore to an earlier point in time, or download a backup.
- **Before risky changes** (a new migration, bulk admin edits): download a fresh export from the same **Recovery** page and keep it somewhere private. It contains waitlist emails.

## Rotate ADMIN_SECRET

Do this if the secret may have leaked, or when someone with admin access leaves.

1. Render dashboard → `patternpilot` → **Environment** → `ADMIN_SECRET` → **Edit**. Paste a new long random value. Generate one in Terminal with `openssl rand -base64 32`.
2. **Save, rebuild, and deploy.** The old secret stops working once the new version is live.
3. Store the new value in your password manager. Never put it in the repo, a chat message, or a `VITE_` variable.

## Check that a deploy is healthy

- `https://<your-domain>/api/healthz` returns `{"status":"ok"}`.
- `https://<your-domain>/api/admin/questions` returns **401** in a browser (no secret).
- `/admin/questions` loads but asks for the secret before it shows anything.
- One passage: Check answers → pattern card → drill → Progress.

## What's not set up (deferred to v0.3, see product.md §3)

Error monitoring, extra backups, waitlist rate limiting, shared session storage, and multiple instances.
